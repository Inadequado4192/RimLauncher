# Release Checklist

1. Завершити заплановані функції та виправлення.
2. Перевірити роботу застосунку локально (`dev build`).
3. Оновити `BACKLOG.md`, якщо потрібно.
4. Оновити `CHANGELOG.md`, додавши секцію для нової версії (`vX.Y.Z`).
5. Збільшити версію в `package.json`, щоб вона відповідала новому релізу (`X.Y.Z`).
6. Оновити `package-lock.json` відповідно до нової версії за допомогою `npm install --package-lock-only`.
7. Виконати локальну збірку та перевірити її:
   - `npm run make`
   - Перевірити згенерований `release-notes.md`.
   - Перевірити створений інсталятор.
8. Створити коміт із підготовленими змінами.
9. Запушити коміт у `main`.
10. Створити Git-тег для нової версії (`vX.Y.Z`).
11. Запушити тег на GitHub. Це запускає GitHub Actions workflow.
12. Перевірити успішність `Validate release`.
13. Дочекатися завершення всіх збірок.
14. Перевірити GitHub Release:
    - Правильність назви.
    - Наявність Release Notes.
    - Наявність усіх файлів для завантаження.
15. Якщо реліз створений як Draft — опублікувати його вручну через GitHub.
